# Bancadas (C2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** abrir até quatro cenas ao mesmo tempo — quatro imagens para comparar, ou a mesma placa em quatro datas — cada uma com imagem, marcações, contornos, histórico, metadados e calibração próprios, com uma delas ativa.

**Architecture:** `useBancada()` compõe os hooks que **já são por-cena** (`useImageQueue`, `useMarks`, `useMetadata`, `useZoom`, `usePanning`) mais o estado de cena que hoje mora solto no `App.tsx` (imagem achatada, ajustes, máscara, contorno selecionado, região, contexto de dataset). O `App` passa a chamar `useBancada()` **quatro vezes, sempre** — hooks não podem ser chamados em laço condicional, e quatro instâncias de estado vazio não custam nada: o peso está nas imagens, e imagem só existe depois de carregada. `abertas` (1–4) decide quantas aparecem; `ativa` decide com quem a barra de ferramentas, os atalhos e o painel direito conversam.

**Tech Stack:** React 19, TypeScript com `strict` parcial (`strictNullChecks` + `noImplicitAny` ligados em 16/09), Dexie, Vitest (ambiente **node**, sem DOM e sem biblioteca de render).

**Spec:** `docs/superpowers/specs/2026-09-15-fila-bancadas-lote-eixos.md`, seção **C2** (desenho aprovado pelo Enrico em 16/09).

### Task 2: `useBancadas()` — quatro instâncias, uma ativa

**Files:**
- Create: `src/hooks/useBancadas.ts`

**Interfaces:**
- Consumes: `useBancada` (Task 1).
- Produces:

```ts
export const MAXIMO_DE_BANCADAS = 4;

export interface Bancadas {
  /** Sempre quatro — hooks não podem ser chamados em laço condicional. */
  todas: Bancada[];
  /** Quantas aparecem na tela: 1 a 4. */
  abertas: number;
  /** Índice da ativa em `todas`. */
  indiceAtivo: number;
  ativa: Bancada;
  ativar(indice: number): void;
  /** Abre mais uma (até 4) e a torna ativa. Devolve o índice, ou null se já há quatro. */
  abrirNova(): number | null;
  /** Fecha uma bancada: zera o estado dela e reordena; nunca fecha a última. */
  fechar(indice: number): void;
}

export function useBancadas(opcoes?: { onImageLoaded?: (b: number, img: HTMLImageElement, file: File) => void }): Bancadas;
```

**Por que quatro sempre:** `useBancada()` chamado quatro vezes custa quatro conjuntos de `useState` vazios — barato. O que pesa é a imagem, e `image` é `null` até alguém carregar. A alternativa (um componente por bancada, com o hook dentro) é mais elegante e muito mais invasiva: exigiria mover metade do App para dentro do componente da cena. Fica registrada como o caminho da versão seguinte, se a comparação entre bancadas exigir.

### Task 4: Memória — bancada inativa não segura a imagem cheia

**Files:**
- Modify: `src/hooks/useBancada.ts` (guarda a versão reduzida e o `File` de origem)
- Modify: `src/features/bancadas/Bancadas.tsx` (pede a reduzida quando inativa)

**Por quê:** quatro digitalizações de 6800×9359 são ~1 GB de bitmap descomprimido. Um tablet cai.

**Regra:** ao sair de ativa, a bancada gera uma versão reduzida (maior lado ≤ 2000 px) para exibição e **libera o bitmap cheio**; ao voltar a ativa, recarrega a cheia do `File` original (que a fila já guarda). Anotações, histórico e metadados **não** são afetados — só pixels. Enquanto a cheia recarrega, a reduzida continua na tela: nada pisca.

- [ ] Steps: implementar → medir com quatro digitalizações reais (`performance.memory` quando existir, senão o tempo de troca) → registrar o número no progresso → commit.

**O que entrou:**

- `src/features/bancadas/Bancadas.tsx` — layout 1/2/2×2. Com uma bancada aberta devolve `children` sem wrapper (`if (abertas <= 1) return <>{children}</>`): o layout de hoje não ganhou nem perdeu um pixel. Com duas ou mais, cada bancada vira uma célula de grade com cabeçalho de 24px (nome truncado + contagem + botão de fechar) e borda 2px (`border-accent` na ativa, `border-line` nas outras). O botão de fechar só aparece dentro do ramo de 2+ bancadas — que é sempre o caso ali dentro, já que o ramo de 1 bancada sai mais cedo.
- **Ativar por clique sem custar um clique extra:** `onClickCapture` no wrapper de cada célula chama `ativar(indice)` na fase de CAPTURA — antes do clique (fase de bolha) alcançar o botão "Procurar Arquivo" do `EmptyState` ou o canvas de marcação da ativa. Sem `stopPropagation`: o clique original sempre completa seu próprio efeito no mesmo gesto.
- **Só a ativa monta overlay caro.** As inativas usam `CenaInativa` (`React.memo`, props primitivas mais os dois arrays que só trocam de referência quando a bancada muda de verdade): reusa `ImageViewport` + `MarkingCanvas` para desenhar imagem, contornos e marcas, mas sem `contornoSelecionado`, sem `mostrarEixosDeTodos`, sem `showRulers`, sem `children` — `MarkingCanvas` já só monta o eixo de PCA, as réguas e o cursor da borracha quando o prop correspondente pede, então bastou não entregar o motivo. As sementes fantasma, o Germinar e a escala gráfica nem aparecem na árvore de uma inativa: só existem dentro do bloco `children`, que só a ativa recebe.
- **Automação amarrada à bancada errada, corrigida:** `onImageLoaded` (em `App.tsx`) já resolvia a bancada certa para zoom/metadados/dataset — mas o "ensaio ao carregar" (a Fase I por trás da flag) rodava para qualquer bancada que terminasse de carregar uma imagem, ativa ou não. Ganhou o guard "só se for a bancada ativa": carregar numa bancada fora de tela não dispara mais um ensaio caro que ninguém vai ver. O painel Encontrar, a medição de pasta e o lote já liam imagem/marcas/metadados vindos da bancada ATIVA — por construção, nunca tocavam bancada nenhuma além dela; não precisaram de mudança.
- **Worker de inferência, resultado × bancada que pediu:** o worker já cancelava a chamada anterior quando uma nova começa (a mais recente vence) — isso cobre trocar de bancada E pedir uma detecção nova nela. O buraco era trocar de bancada SEM pedir nada na nova: nada cancela a inferência da bancada antiga, e o resultado chegaria sozinho. O painel de IA ganhou uma prop com o id da bancada ativa no momento do render; o pedido de detecção captura esse id ANTES de esperar o resultado e, quando ele chega, compara com o id mais recente — descarta se a bancada mudou. Um segundo efeito zera a detecção pendente sempre que a bancada ativa muda, para "Confirmar" nunca aplicar à bancada nova um resultado ainda não confirmado da antiga.
- **Bancada fechada não renderiza nem decodifica:** `Bancadas.tsx` itera só as bancadas dentro de `abertas` — um slot fechado nunca aparece na árvore, então nunca passa pelo desenho do canvas.
